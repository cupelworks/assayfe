# Assay FE

Angular 22 front-end for the Assay evaluation API (v0.9.4). Modernist design system (Archivo, red/ink on light ground, zero radius, 2px rules); dark mode via `[data-theme="dark"]`.

## Run
```
npm install
npm start          # http://localhost:4200
```
Backend must allow CORS from `http://localhost:4200`. API base is set in `src/app/app.config.ts` (`ASSAY_API_BASE`).

## Screens → endpoints
- **Overview** - counts, recent test-set/test-plan executions, and a "Run status" box (`GET /runs`, 500 newest, every origin) whose six tiles (Pending/Running/Green/Amber/Red/Not Ran) each link to the filtered **Runs** list below. New test.
- **Runs** (`/runs`) - every run in the system (`GET /runs`), optionally filtered server-side by `?status=`/`?origin=` (set from the Overview tiles or the on-page origin chips). Per-row name resolved with one lookup call each (`GET /tests/{id}` for Standalone, `GET …/test-runs/{run}` for Test set/Test plan). Created column sorts client-side (arrow toggle) over whatever page is loaded. Run id is click-to-copy.
- **Datasets** - list (name-filterable, Created sortable); *Import from JSONL* (`POST /datasets/path`). **Dataset detail** - paged rows (`GET /datasets/{id}/rows`), edit row (`PATCH /datasets/rows`), add rows / replace all rows (paste JSONL → `POST`/`PUT /datasets/rows`), delete selected rows (`DELETE /datasets/rows`), rename (`PATCH /datasets/name`), delete (`DELETE /datasets`), *Create tests from rows* (`POST /tests/from-dataset`).
- **Tests** - list, filter, bulk delete (`DELETE /tests`), New test (`POST /tests`). **Test detail** - edit (`PATCH /tests/{id}`), delete, *Run standalone* (`POST /runs/standalone/{id}`), standalone runs list (status + click-to-copy run id, independent of the row's own link) → **Standalone run detail** (`GET /runs/standalone/{id}/test-runs[/{run}]`).
- **Test sets** - list (with an Entries column, free from `entry_count` on `GET /test-sets`), New (`POST /test-sets`). **Test set detail** - entries (`GET …/entries`, each tagged "frozen" once it has a run against it), *Add tests* (`POST …/entries` `[{id}]`), *Unlink* (`PATCH …/entries`), *Delete entries* (`DELETE …/entries`), edit frozen entry (`PATCH …/entries/{entry}`), rename, delete, *Run live* (`POST /runs/test-sets/{id}`), executions (per-row status breakdown, click-to-copy id, "replayed" reference linked, polls while anything shown is Pending/Running) + *Replay* (`POST /runs/test-sets/{id}/executions/{exec}`).
- **Test plans** - list (Linked sets column, free from `linked_set_count` on `GET /test-plans`), New. **Test plan detail** - linked sets (`GET …/entries`, each row's Entries count free from the embedded `test_set.entry_count`), *Link* (`POST …/entries`), *Remove* (`DELETE …/entries`), rename, delete, Run live / Replay under `/runs/test-plans/…`.
- **Execution** - status counts (current page only) + run list (`GET …/executions/{exec}/test-runs`) with a per-row Results bar (pass/fail share + "x/y", from the same per-row `test-runs/{run}` call already made for the name), Created and Executed columns both independently sortable (arrow toggle, unfinished runs sort last), click-to-copy Entry/Run ids, Replay, polls while any loaded row is Pending/Running. **Run detail** - status, per-type results with the config actually checked against (e.g. "Minimum score to pass: 0.75"; long values like a rubric clamp behind a More/Less toggle), frozen entry snapshot (`GET …/test-runs/{run}`), link to originating test, polls while the run itself is Pending/Running.
- **Test types** - catalogue from `GET /tests/types?test_category=…` (all three categories fetched in parallel), cached by `TestTypesStore` for reuse in the test forms and in run detail's config labels. Category tiles show an active-only count and a one-line blurb; click one to narrow the list to just that category, click again to clear. A legend tile explains the `fast` / `needs reference` / `inactive` tags. Below that: text filter, show-inactive toggle, a page-scoped Refresh (force-reloads the type catalogue past its normal load-once cache), and cards (description, best for, limitations, cost, needs-reference) that expand on click for category, reference requirement, and added date.
- **Guide** - static "How Assay works" explainer: the core dataset/test/test-set/test-plan model, the freeze-on-execution rule, standalone vs. live vs. replay runs, three concrete end-to-end workflows, test-plan linking, run statuses, and a guardrail FAQ. No API calls.

## Structure
`api/` models + one-method-per-endpoint service + root `CatalogStore` + `TestTypesStore` · `shared/` formatters, page.css, `Paged`/`PagerComponent`, `DateSort`, `TextFilter`, `pollWhile`, `<assay-rel-time>`, `<assay-copy-button>`, dialogs (generic, name, confirm, pick, test form), test-type-picker · one folder per area (`datasets`, `tests`, `scopes`, `runs`, `test-types`, `guide`) · `shell/` header/footer/theme.

## Notes
- Test types: every form (new/edit test, edit entry, create tests from dataset) uses `shared/test-type-picker` - grouped by category, with smart filtering: inactive types are hidden unless the test already has one assigned, a search box narrows by name/description/best-for, category chips narrow to one group, and a "Hide types needing setup" toggle filters out any type with an unmet *required* `config_fields` entry - not just a missing reference, any required config (a rubric, say) counts too. Each such type also shows a "needs setup" tag per row regardless of the toggle. Assigned names no longer in the catalogue are listed separately as removable chips.
- Pagination: every list the API pages (`?offset&limit` + `total`) has a shared pager (Previous/Next, range label, 5/10/25/50 per page) - datasets, dataset rows, tests, test sets/plans, set entries, plan links, executions, execution runs, standalone runs, and the global runs list. `shared/paged.ts` holds the page state; `shared/pager.component.ts` renders it. The `CatalogStore` still preloads the first 100 of each catalog for counts, name lookups and the overview. Text filters apply to the current page only. The execution page's status tiles summarise the current page (no aggregate endpoint). Runs are enqueue-only - status stays `Pending` until the worker runs; five pages (execution detail, both run detail variants, test detail's standalone runs, the executions panel) poll every 15s while they're showing a Pending/Running row and stop the instant it settles (`shared/poll.ts`). Nothing else auto-refreshes - the global runs list, Overview, and every catalogue page still just reload on next visit (or the test types page's own manual Refresh button).
- Delete buttons are pre-disabled where the API would 409 (set/plan with executions); other 409s (tests in sets, entries with runs) are shown verbatim.
